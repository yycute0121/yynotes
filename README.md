# WorkBuddy · 个人物品与事务管理工作台

纯前端、本地优先的个人管理工具。莫兰迪低饱和配色，移动端优先，可安装到手机桌面后断网使用。

四个模块全部完成，并提供 ZIP 备份导出与恢复。

## 特点

- 无后端、无登录、无数据库服务
- 数据与图片只保存在本机 IndexedDB
- 零外部依赖：不引用任何 CDN、远程字体或图标库
- 支持 PWA 安装，断网可继续浏览与录入
- 一键导出完整备份，随时恢复

## 四个模块

### 电子物品档案

设备名称、品牌型号、购入渠道/日期/价格、保修到期、硬件参数、多张实拍照片、维修历史、备注。

派生数据每次打开都实时重算，数据库只存原始日期：

- 已使用天数（以购入日期为起点）
- 保修剩余天数，30 天内警示，过期标「已过保」
- 预计更换提醒（购入日期 + 预计更换年限），90/30 天分级

支持分类自定义增删改、关键词搜索、按使用时长或保修到期排序。

### 事件记录本

两种模式：

**随手一记** 极简笔记，可插图，没有预算与进度字段。

**重大事件** 项目模式，内含四个区块：

- 任务清单：待办/进行中/已完成三态循环，按完成率生成进度条
- 预算管理：总预算 + 逐笔支出，自动算已花费、剩余、超支
- 时间规划：目标截止日期与倒计时
- 素材附件：图片自动压缩，PDF 等原样保存
- 日志备注：记录沟通结果与重要决定

预置婚礼筹备、买房置业、旅行规划、装修、备考、购车，可自定义。

### 生活用品库存

商品、分类、数量、单位、购入日期、保质期、单价、存放位置、补货阈值。

- 保质期分级：7 天内重点提醒，30 天内轻提醒，过期明确标示
- 列表按临期优先排序
- 步进器直接加减数量，减少时自动记一笔消耗流水
- 低于阈值进入待补货列表

### 电子衣柜

| 子模块 | 能力 |
| --- | --- |
| 我的衣橱 | 拍照/相册导入、本地去背、分类与季节筛选、搜索 |
| 想买清单 | 想买/犹豫/已购入状态、商品链接、价格备注 |
| 数字人物 | 上传全身照作为画布素材，可设默认。不做 AI 试穿、不做人脸识别 |
| 搭配画布 | 触摸拖拽、双指缩放、手柄缩放、图层调整、保存并生成预览图 |

## 存储用量预警与备份提醒

数据只在本机，配额用满会导致新照片保存失败，长期不备份则有丢失风险。两件事都做了主动提示。

**存储用量分级**（`js/health.js`）

同时看百分比和剩余绝对空间，避免配额差异导致误判：

| 分级 | 条件 | 表现 |
| --- | --- | --- |
| 充足 | < 65% 且剩余 > 200MB | 绿色标签 |
| 偏高 | ≥ 65% 或剩余 < 200MB | 黄色标签，首页提示可忽略 |
| 紧张 | ≥ 85% 或剩余 < 50MB | 红色标签，首页始终提示 |

设置页显示已用、配额、剩余、图片附件个数，并给出可执行建议（先导出备份再清理）。

**备份提醒**

导出成功后记录时间与当时的记录总数。触发条件：

- 有数据但从未备份 → 提醒
- 超过提醒周期（默认 14 天，可选 7/14/30 或关闭）→ 提醒
- 超期且期间有新增记录 → 升为高优先，文案带上「新增 N 条」
- 没有任何数据时不打扰

首页提醒条可「今天不再提醒」，但存储紧张级别始终显示。提醒只在界面呈现，不发起任何网络请求，也不做自动上传。

## 备份与恢复

「数据与存储」页可导出为 ZIP：

```
WorkBuddy备份_20260731_1420.zip
├── manifest.json      版本、导出时间、各模块条数
├── data.json          全部记录（含 blobId 引用）
└── blobs/<id>.webp    原始图片与附件
```

自己实现 ZIP（store 模式，不二次压缩），原因：

- 项目不允许引入任何第三方库
- 图片已是 webp/jpeg，二次压缩收益低
- 比 base64 塞进 JSON 省 33% 体积
- 你能直接用系统解压看到照片，不依赖这个应用

导入前先完整解析与校验，展示条数摘要，再选择合并或替换。写入走 **IndexedDB 单事务**，任一步失败自动回滚，所以导入失败不会破坏现有数据。若备份被外部工具重新压缩成 deflate，用浏览器内置 `DecompressionStream` 兜底解析。

## 内存与存储控制

图片是这类应用最容易爆的地方，实测 2400×3200 的 PNG 从 36MB 降到约 177KB：

1. **入口即压缩**：任何图片先降到长边 1280px 才落库，原图不进数据库
2. **双份产物**：每张图存 `full` 与 `thumb`（长边 320），列表只读缩略图
3. **元数据与二进制分表**：业务表只存 `blobId`，图片放独立 `blobs` 表，列表查询不碰大图
4. **懒加载**：缩略图通过 `IntersectionObserver` 在进入视口前后才解码
5. **ObjectURL 引用计数**：URL 按页面分组，切页与页面隐藏时整组回收（实测切页后归零）
6. **及时释放**：`ImageBitmap` 用完 `close()`，临时 canvas 用完宽高置 0
7. **画布素材上限 14 个**，避免同时驻留过多解码位图
8. **删除即回收**：删除记录时连带清理其图片与附件，不留孤儿 Blob
9. **导出流式打包**：逐个文件算 CRC 后只保留 Blob 引用，峰值内存约等于单个最大文件

## 本地去背

不加载任何 AI 模型，采用边缘采样 + 容差 flood fill + alpha 羽化：从四边向内扩散，去掉与背景色相近的连通区域。对白底和纯色底的电商图效果好，纯本地计算，可用滑块调强度。复杂背景建议关掉该选项。

## 主题

默认锁定奶油浅米杏，**不跟随系统深色**。这是刻意的选择：浅米杏低饱和是本应用的核心视觉，系统反转会破坏莫兰迪的柔和观感。深色是「数据与存储」页里的手动开关，偏好存本机。

浅色模式实测配色（饱和度均压在 13% 以内）：

| 位置 | 色值 | 饱和度 |
| --- | --- | --- |
| 背景 | `#EFEAE3` | 5.0% |
| 电子物品档案 | `#CBD3D7` 雾蓝 | 5.6% |
| 事件记录本 | `#D8D2DA` 藕紫 | 3.7% |
| 生活用品库存 | `#CFD6C9` 鼠尾草 | 6.1% |
| 电子衣柜 | `#E2D2C6` 陶土 | 12.4% |

所有文字与徽章的对比度按 WCAG AA 校准，浅色与深色两套主题各 18 项组合全部达标（`tools/contrast_test.py`）。状态色（成功/警示/危险）有两种用法——徽章文字色配同名浅底，以及实心按钮底色配浅色文字——两种都要达标，因此比常见莫兰迪配色更深一档；深色主题下这三个色反向提亮，按钮文字改用 `var(--surface)` 自动跟随。

浅色主题实测：问候语 8.44:1，卡片标题 6.65:1，描述 3.72:1，警示徽章 3.91:1。

## 本地运行

Service Worker 需要 http 环境，直接双击 `index.html` 会跳过离线注册（其余功能正常）。建议起静态服务：

```bash
cd workbuddy
python3 -m http.server 8777
# 打开 http://127.0.0.1:8777
```

改动 CSS 或 JS 后记得提升 `service-worker.js` 里的 `CACHE` 版本号，否则浏览器会继续用缓存里的旧资源。

## 部署到 GitHub Pages

仓库根目录已含 `.nojekyll`，确保下划线开头的文件也能正常发布。

```bash
cd workbuddy
git init
git add .
git commit -m "feat: 四个模块与本地备份恢复"
git branch -M main
git remote add origin https://github.com/yycute0121/yynotes.git
git push -u origin main
```

推送后在 **Settings → Pages** 把 Source 设为 `main` 分支根目录，发布完成后访问：

```
https://yycute0121.github.io/yynotes/
```

若作为子目录提交（如仓库下的 `workbuddy/`），地址相应加上子目录名。所有资源都用相对路径，两种方式都能正常工作。

## 手机离线使用

1. 手机联网打开 Pages 地址
2. iOS Safari 选「分享 → 添加到主屏幕」；Android Chrome 选「添加到主屏幕」
3. 之后从桌面图标打开，断网也能使用

清理浏览器数据或卸载 PWA 会一并删除本地数据，**重要内容请先导出备份**。

## 数据模型

| 表 | 内容 |
| --- | --- |
| `devices` | 设备档案，`photos` 内嵌图片引用数组 |
| `notes` | 随手笔记，`images` 内嵌图片引用 |
| `projects` | 重大事件，`tasks`/`expenses`/`logs`/`attachments` 内嵌 |
| `inventory` | 库存商品，`consumes` 内嵌消耗流水 |
| `clothes` `wishlist` `avatars` `outfits` | 电子衣柜 |
| `blobs` | 所有图片与附件二进制，按 id 引用 |
| `meta` | schema 版本、自定义分类、备份时间与提醒周期 |

项目与库存的子项内嵌在主文档里，单条记录的子项数量有限，内嵌能让一次 `put` 保持整体一致，避免跨表事务。
